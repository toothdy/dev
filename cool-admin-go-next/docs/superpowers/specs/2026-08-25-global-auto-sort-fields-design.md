# CRUD 自动排序字段设计

## 1. 背景

前端通用列表组件会向分页接口提交 `order` 和 `sort`。当前 CRUD 运行时只有控制器显式配置 `SortFields` 后才允许客户端排序，而现有业务控制器均未配置该字段，导致 `/admin/dict/type/page` 等接口在收到 `createTime` 排序时返回 `1002`。

`createTime` 已存在于实体 Descriptor 和数据库表中。故障原因是排序策略没有为未配置控制器提供默认字段，并非请求格式、字段命名或 ORM 映射错误。

## 2. 目标

1. CRUD 的 `list`、`page` 动作在未配置 `SortFields` 时，允许按实体的持久化字段排序。
2. 保留显式 `SortFields` 的严格白名单语义。
3. 隐藏字段不得因自动排序而暴露可观察的信息。
4. 保留现有排序参数校验和 SQL 标识符安全边界。

## 3. 非目标

1. 不改变 `add`、`delete`、`update`、`info` 动作。
2. 不自动增加默认排序；未提交 `order`、`sort` 时保持现有查询顺序。
3. 不允许关联表字段、投影别名或请求提供的任意字符串自动参与排序。
4. 不新增控制器配置项。

## 4. 设计

### 4.1 自动字段来源

编译 `list` 或 `page` 动作的字段策略时，如果 `SortFields` 为空，则遍历根实体 Descriptor 的 `Fields()`。每个字段使用 Descriptor 提供的 JSON 名作为请求白名单键，并使用已解析的数据库列信息构造排序列。

自动字段只来自已编译的 Descriptor，不拼接请求中的字段名，因此未知字段仍在生成 SQL 前被拒绝。

### 4.2 隐藏字段

自动生成排序字段时跳过 `HiddenFields`。例如用户实体的 `password` 即使属于持久化字段，也不能通过排序参数间接观察其数据分布。

`ReadonlyFields` 和 `InfoIgnoreProperty` 不影响排序。它们分别约束写入和详情投影，不代表字段对列表查询不可见。

### 4.3 显式白名单

当 `SortFields` 非空时，不执行自动生成，继续只允许控制器声明的字段。现有需要限制排序范围的控制器无需迁移；配置一个或多个字段即可覆盖全局默认行为。

空切片与未配置在 Go 中保持相同语义，均启用自动字段。当前不增加单独的“禁止客户端排序”开关；需要禁止某字段时，控制器应声明更窄的非空白名单。

### 4.4 动作边界

自动策略仅为 `list`、`page` 编译。其他动作继续沿用现有字段策略流程，避免无排序需求的动作新增 Descriptor 前置条件或改变错误行为。

### 4.5 错误处理

以下校验保持不变：

- `order` 与 `sort` 必须同时存在且数量一致；
- 排序方向只能是 `asc` 或 `desc`；
- 未知字段、隐藏字段以及不在显式白名单中的字段返回校验错误；
- 显式 `DefaultSort` 仍必须位于显式 `SortFields` 中。

## 5. 修改范围

1. `cool-next/crud/action_plan.go`：为 `list`、`page` 的空排序配置编译非隐藏实体字段。
2. `cool-next/crud/action_plan_test.go`：覆盖自动字段、隐藏字段排除和显式白名单优先级。

业务控制器、实体、数据库和前端均不修改。

## 6. 验证

1. 空 `SortFields` 的分页计划接受实体字段 `createTime asc`。
2. 空 `SortFields` 且配置 `HiddenFields` 时，隐藏字段排序被拒绝，普通字段排序成功。
3. 非空 `SortFields` 继续拒绝实体中存在但未声明的字段。
4. 运行 `go test ./cool-next/crud -count=1`。
5. 条件允许时复测 `/admin/dict/type/page`，确认原请求不再返回 `1002` 且结果按 `createTime ASC` 排序。

## 7. 风险与约束

自动允许非隐藏持久化字段后，调用方可以请求未建索引字段排序，较大数据集可能产生慢查询。控制器可通过显式 `SortFields` 收紧高风险接口；本次不引入索引感知或字段类型过滤，避免把性能策略混入通用 CRUD 编译器。
