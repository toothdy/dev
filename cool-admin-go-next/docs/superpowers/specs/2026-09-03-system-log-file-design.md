# 系统日志文件配置设计

## 目标

应用通过 GoFrame 官方 `logger` 配置管理 `g.Log()` 的系统运行日志。默认写入项目 `logs` 目录并保留终端输出，部署时可以使用 GoFrame 支持的完整日志配置覆盖默认值。

## 实现

- 两份应用 YAML 在根节点声明标准 `logger` 配置，默认使用 `path: logs`、`file: "{Y-m-d}.log"`、`level: all` 和 `stdout: true`。
- 入口先按 `COOL_CONFIG_FILE` 或默认路径解析应用实际配置文件，再始终将 GoFrame 配置适配器显式指向该文件，避免 `GF_GCFG_FILE` 等框架环境变量造成配置来源分叉。
- 配置适配器设置完成后再首次获取 `g.Log()`，由 GoFrame 自动解析和应用 `logger` 节点。
- 未配置 `logger.path` 时，入口调用 `Logger.SetPath("logs")` 作为文件输出兜底。
- 项目强类型配置加载前移除由 GoFrame 管理的 `logger` 根节点，避免将第三方组件配置重复映射为项目配置类型。
- 将 `/logs/` 加入 `.gitignore`，不提交运行时日志。

## 错误处理

GoFrame 配置适配器或兜底日志目录初始化失败时，将脱敏错误输出到终端并以状态码 `1` 退出。此时不继续启动应用，避免系统在日志不可用的情况下运行。`level` 等日志字段无效时，沿用 `g.Log()` 初始化失败并 `panic` 的官方快速失败行为。

## 边界

- 不修改写入 `base_sys_log` 的后台操作日志。
- `logger` 只控制项目通过 `g.Log()` 输出的系统运行日志；HTTP Server、gRPC 和 ORM 组件日志仍遵循各自的 GoFrame 配置。
- 不自定义 GoFrame 日志配置类型或重复实现级别、轮转和压缩解析。
- 默认配置不启用轮转、压缩或历史文件清理；部署时可直接使用 GoFrame 官方字段开启。
- 不增加第三方依赖，也不修改生成代码的基础设施配置结构。

## 验证

- 运行格式检查和 Go 测试。
- 验证强类型配置加载会忽略交给 GoFrame 的 `logger` 节点，其他未知根字段仍会被拒绝。
- 验证 `COOL_CONFIG_FILE` 与 GoFrame 使用同一份配置文件。
- 使用临时工作目录启动可执行文件，验证生成 `logs/<当天日期>.log`。
- 验证日志仍同时输出到终端。
