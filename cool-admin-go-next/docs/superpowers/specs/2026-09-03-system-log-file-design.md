# 系统日志文件设计

## 目标

应用启动后将 GoFrame `g.Log()` 的系统运行日志写入项目 `logs` 目录，同时保留终端输出。

## 实现

- 在应用入口调用 GoFrame `Logger.SetPath("logs")`，并在装配应用前完成初始化。
- 使用 GoFrame 默认文件名 `{Y-m-d}.log`，每天写入对应日期的日志文件。
- 保留 GoFrame 默认 `stdout: true`，便于本地开发和容器采集。
- 将 `/logs/` 加入 `.gitignore`，不提交运行时日志。

## 错误处理

日志目录初始化失败时，将脱敏错误输出到终端并以状态码 `1` 退出。此时不继续启动应用，避免系统在日志不可用的情况下运行。

## 边界

- 不修改写入 `base_sys_log` 的后台操作日志。
- 不增加日志轮转、压缩或历史文件清理；需要时再独立配置。
- 不增加第三方依赖，也不修改应用强类型配置结构。

## 验证

- 运行格式检查和 Go 测试。
- 使用临时工作目录启动可执行文件，验证生成 `logs/<当天日期>.log`。
- 验证日志仍同时输出到终端。
