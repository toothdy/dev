# SVG Path 验证码设计

## 目标

将 Base 模块验证码从 PNG 位图切换为 SVG Path，保持现有接口字段、验证码 ID、30 分钟有效期、大小写不敏感校验和成功后一次性消费逻辑不变。

## 实现

- 使用 `github.com/reu98/go-svg-captcha v1.2.2` 将服务端生成的四位随机字符转换为 SVG Path。
- 使用 Go 标准库 XML 解析生成结果，只保留没有 `stroke` 属性的字符 Path，移除库默认生成的曲线和噪点，避免干扰元素影响可读性。
- 将字符 Path 的填充色统一设置为经过现有十六进制颜色校验的颜色值。
- 接口继续通过 `data` 字段返回 Base64 Data URL，媒体类型改为 `image/svg+xml`。
- 验证码答案只写入服务端缓存，不在 SVG 中输出 `<text>`、注释或其他明文字段。

## 错误处理

第三方库生成失败、SVG 解析失败或未获得预期数量的字符 Path 时，本次生成失败且不写入缓存，沿用现有业务异常包装。

## 测试

- 校验默认及自定义宽高、颜色和非法参数回退。
- 校验返回值是可解析的 SVG Data URL。
- 校验 SVG 不包含 `<text>`、干扰曲线、噪点或验证码明文，并且恰好包含四个字符 Path。
- 保留验证码有效期、错误输入不消费、正确输入一次性消费和并发仅成功一次的测试。

## 范围

仅修改验证码依赖、生成服务和对应测试，不改动控制器、DTO、登录校验及前端协议。
