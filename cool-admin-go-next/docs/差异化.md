- 复核日期：2026-08-15
- Go 项目：`/Users/n/数据/cool-admin/cool-admin-go-next`
- Node 主仓：`/Users/n/数据/cool-admin/cool-admin-midway`
- Node 公共包：`/Users/n/数据/cool-admin/cool-admin-midway-packages`
- Go 当前基线：`HEAD 3d57835 feat(outbox): 集成配置生成图与 Host`
- 核查范围：框架能力和公共核心包
- 排除范围：业务模块、业务实体、业务 Controller、业务 Service、业务菜单、业务权限数据和业务流程

## 1. 判定口径

本文只比较功能，不比较实现方式、代码组织、API 名称或技术选型。

为避免把 GoFrame 的底层 API 当成 Go-next 已经提供的 Cool 功能，状态分为：

| 状态 | 含义 |
|---|---|
| **已具备** | Go-next 框架源码已经提供该功能，或 GoFrame 原生功能已被 Go-next 当前代码实际使用 |
| **框架具备，当前应用未接入** | Go-next 源码或生成器已经有该能力，但当前 `modules/modules_gen.go` 没有把它装配进启动应用 |
| **GoFrame 底层可用，Go-next未接入** | GoFrame v2 有底层 API，但 Go-next 当前生产源码没有接入该功能 |
| **部分具备** | 只有部分功能或相近能力，不能视为完整等价 |
| **缺失** | Go-next 与 GoFrame 均没有可提供相同功能的能力 |
| **不纳入** | 属于业务模块，本次不评估 |

特别注意：

- `gcache`、`gcron`、`ghttp`、`gdb`、`glog`、`gvalid` 等 GoFrame 底层组件存在，不代表 Go-next 已经提供与 Node 高层包相同的产品功能。
- `@CoolCache` 不能仅因为 GoFrame 有 `gcache` 就判定为已对齐。
- BullMQ 不能仅用 Redis 或 Outbox 代替。
- Moleculer RPC 不能仅用 gRPC 代替。

## 2. 当前 Go-next 实际状态

### 2.1 框架源码状态

Go-next 当前已经包含以下框架源码：

- Application Host、Assembly 和生命周期管理
- 强类型配置与环境覆盖
- Controller、路由、Binder、统一响应
- CRUD Dispatcher、QueryPlan、Service Base
- Entity Descriptor、DO 和 Schema
- JWT、Session、bcrypt、Authorizer
- 数据库 Runtime、事务、Schema、Recycle
- EPS 编译器
- HTTP/gRPC Transport
- Transactional Outbox/Inbox、Worker、Consumer Runtime
- `cool generate/check/build/run` CLI
- `cool outbox list/show/replay` 运维 CLI

### 2.2 当前生成应用状态

当前 `/Users/n/数据/cool-admin/cool-admin-go-next/modules/modules_gen.go` 仍只有 `.framework` 模块：

- `generatedHTTPInstaller` 为空实现；
- gRPC Registrar 为空实现；
- 没有业务 Controller、Route、Entity Descriptor 或 Service；
- 当前 `assemble` 只构造 HTTP 和 gRPC Transport；
- 没有实际构造 DB Runtime、Recycle Store、Outbox Store、Worker 或 Consumer Runtime；
- `manifest/config/config.yaml` 只有 HTTP/gRPC Transport 配置和 `modules: {}`；
- Outbox 默认关闭。

因此下表会同时区分“框架源码已有”和“当前生成应用已接入”。这不是业务模块缺失判断，而是当前框架装配进度。

| 公共包 | Node 公共功能 | Go-next 当前功能结论 |

## 7. 最终结论

> **按框架源码功能判断，Go-next 已覆盖 Node 核心框架的主要基础能力：配置、校验、HTTP、路由、CRUD、Entity、Service、事务、关系型数据库、异常、JWT、Session、EPS 和可靠 Outbox。**
>
> **按当前实际启动应用判断，Go-next 仍是空框架 Host：HTTP/gRPC Transport 已装配，但没有业务路由、DB Runtime、Auth Transport、EPS 路由或 Outbox Worker/Consumer。**
>
> **把 GoFrame 原生能力计入 Go 侧后，gcache、gcron、ghttp 上传/保存、glog、gvalid、gdb 查询缓存和 ghttp Swagger 只能判为“底层可用”，不能在 Go-next 当前代码未接入时直接判为 Go-next 已对齐。**
>
> **当前真正未对齐的 Node 公共高层功能主要是：`@CoolCache` 方法缓存、Cool Event Manager、BullMQ 队列、Moleculer RPC、Elasticsearch、插件 SDK/发布、MCP、Mongo、磁盘 Cache Store，以及 Node TypeORM 的完整高级 API。**
>
> 本文不评价 Go 侧如何实现，也不判断任何业务模块完成度。
