# 菜单与部门局部更新修复设计

- 日期：2026-07-29
- 项目：`cool-admin-go-next`
- 对照实现：`cool-admin-midway` 8.0.8
- 状态：已批准，待实施

## 1. 背景

菜单和部门的自定义 `Update` 使用包含全部列的 mutation row 结构体。当请求只提交部分字段时，未提交字段在结构体中为 `nil`，GoFrame 将它们展开为 `SET column = NULL`。菜单开关更新因此尝试把 `create_time`、`name` 等列置空，并首先触发 `create_time cannot be null`。

现有 Vue 页面有两种合法提交方式：

1. 表格开关只提交 `id` 和当前字段。
2. 编辑表单提交包含 `createTime`、`updateTime`、`tenantId` 的完整记录。

后端当前又会把完整记录中的 `createTime` 判定为未知字段。因此需同时修复局部更新语义和 Node 兼容的只读字段处理。

## 2. 目标

1. 同时修复菜单和部门更新。
2. 字段未出现时保持原值，明确提交 `null` 时仅对可空列写入 `NULL`。
3. `false`、`0` 和空字符串不得被当作缺失字段。
4. 兼容 Vue 的局部开关请求和完整编辑表单请求。
5. 保留未知字段校验、租户作用域、行锁和父节点校验。
6. 不增加数据库往返、事务范围或高频 JSON 转换。

## 3. 非目标

1. 不重构通用 CRUD Runtime 或租户 Hook。
2. 不修改 Vue 提交方式。
3. 不引入 JSON Patch、JSON Merge Patch 或可选值第三方包。
4. 不扩展到已经正确使用局部更新 map 的用户、角色和参数服务。
5. 不改变当前返回值和错误码协议。

## 4. 技术调研与选型

### 4.1 Node 对照行为

`cool-admin-midway` 的菜单服务不重写更新，而是使用 `@cool-midway/core` 的 MySQL 通用服务。该服务在单记录更新时：

1. 删除客户端提交的 `createTime`。
2. 用服务端当前时间覆盖 `updateTime`。
3. 调用 TypeORM `Repository.update(id, partialEntity)`。

其核心是局部实体更新，不是 TypeScript 特性。

### 4.2 GoFrame 原生能力

项目使用 GoFrame v2.10.2。官方字段过滤能力中：

- `OmitEmptyData` 会过滤 `nil`、`0`、空字符串等空值，不符合更新语义。
- `OmitNilData` 只过滤 `nil`，但也会丢失客户端明确提交 `null` 的意图。
- `Fields` 会在写入前只保留指定列；选中列的 `nil`、`false` 和 `0` 仍保持原语义。

因此采用 `Fields + mutation row`，由请求字段是否存在决定 `Fields` 列表。

### 4.3 第三方方案

`evanphx/json-patch` 实现 RFC 7396 JSON Merge Patch，可以表达缺失和 `null`。但引入它需要把数据库记录转成完整 JSON 文档，再合并、解码和保存。这会增加依赖、CPU 分配、数据库读取和并发覆盖风险，不适合当前的平面字段更新。

## 5. 请求契约

### 5.1 只读字段

更新默认静默忽略：

- `tenantId`
- `createTime`
- `updateTime`

部门额外继续忽略由服务端管理的 `userId`。这些字段不进入未知字段校验，也不得进入 SQL `SET`。

### 5.2 未知字段

删除只读字段后，其他不在业务白名单的字段继续返回 `未知字段: <field>`。不允许通过宽松绑定静默接受拼写错误或越权列。

### 5.3 局部更新语义

| 请求状态 | 行为 |
| --- | --- |
| 字段未出现 | 不加入 `Fields`，保持数据库原值 |
| 字段为 `false` 或 `0` | 加入 `Fields`，正常写入 |
| 可空字段为 `null` | 加入 `Fields`，写入 SQL `NULL` |
| 非空字段为 `null` | 执行 SQL 前返回校验错误 |
| 仅有 `id` 和只读字段 | 仅刷新服务端 `update_time` |

菜单可空更新字段为 `parentId`、`router`、`perms`、`icon`、`viewPath`。部门可空更新字段为 `parentId`。

## 6. 实现设计

### 6.1 模块内转换函数

菜单和部门各自增加一个局部更新转换函数。函数输入为已移除只读字段的 `request.Data`，输出为：

1. 对应的 mutation row。
2. 由客户端实际提交字段映射得到的数据库列表。
3. 输入校验错误。

转换函数是纯数据处理，不访问数据库，便于直接覆盖字段存在性和空值语义。不抽取新的通用 CRUD 转换框架。

### 6.2 服务更新流程

1. 移除兼容的只读字段。
2. 严格校验剩余字段。
3. 解析并校验 `id`。
4. 调用模块内转换函数得到 row 和 fields。
5. 设置服务端 `UpdateTime`，将 `update_time` 加入 fields。
6. 按现有租户作用域开启事务并锁定目标记录。
7. 如果实际提交了正数父 ID，执行现有父节点存在性和租户校验。`parentId: null` 表示移到根节点，不查询父节点。
8. 使用 `Fields(fields).Where("id", id).Data(row).Update()` 更新。

### 6.3 事务与租户边界

保持现有事务结构和 `SELECT ... FOR UPDATE`。更新仍通过 `tenant.ScopedModel` 执行，租户 Hook 继续追加更新谓词并防止修改 `tenant_id`。

不因局部更新修复删除行锁，也不用 `RowsAffected == 0` 替代目标存在性检查，因为 MySQL 对“值未变化”和“记录不存在”的受影响行数语义受连接配置影响。

## 7. 校验与错误处理

1. `name` 如果出现，必须为非空值且去除首尾空白后非空。
2. 非空业务字段明确为 `nil` 时返回 Validate 错误，不依赖 MySQL `NOT NULL` 错误。
3. 父 ID 等于当前 ID 时保持现有“上级不能是自身”错误。
4. 目标不存在、父节点不存在或跨租户时保持现有业务错误。
5. 查询和更新失败继续使用 `gerror.Wrap` 保留错误栈，并回滚整个事务。

## 8. 性能设计

1. 保持现有数据库往返数和事务范围，不增加记录查询。
2. 转换函数仅遍历固定小集合：菜单最多 10 个可编辑字段，部门最多 3 个。
3. SQL `SET` 列数与实际提交字段数成正比，避免无关列写入和索引维护。
4. GoFrame `Fields` 使用的表字段元数据保存在进程内无过期缓存中，常态请求不会重复查询表结构。
5. 不进行完整记录 JSON 编解码，不引入 patch 依赖或反射型 DTO 封装。
6. 性能验收使用 SQL 结构和数据库往返数作为稳定指标，不设置受 CI 机器波动影响的绝对耗时阈值。

## 9. 测试设计

### 9.1 纯函数单元测试

菜单和部门分别覆盖：

- 完整表单的只读字段被忽略。
- 开关局部更新保留 `false`。
- 排序局部更新保留 `0`。
- 缺失字段不出现在 fields 中。
- 可空字段的 `nil` 仍出现在 fields 中。
- 未知字段被拒绝。
- 非空字段的 `nil` 被拒绝。

### 9.2 DryRun SQL 回归测试

使用现有 GoFrame DryRun 数据库和预置表字段元数据，断言：

- `SET` 只包含实际更新列和 `update_time`。
- `SET` 不包含 `create_time`、`tenant_id` 或未提交列。
- `WHERE` 仍包含当前租户谓词。
- 明确提交的可空字段生成 `column = NULL`。

### 9.3 MySQL 集成测试

扩展 `COOL_CUSTOM_API_INTEGRATION=1` 的真实 MySQL 场景，执行：

1. 菜单开关局部更新。
2. 带只读字段的菜单完整表单更新。
3. 部门局部更新。
4. 可空父节点清空。
5. 跨租户父节点更新拒绝。

每次更新后重新读取数据库记录，确认未提交字段、`create_time` 和租户归属保持不变，`update_time` 由服务端刷新。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| `Fields` 列表遗漏已赋值字段 | 纯函数测试同时断言 row 和 fields |
| 将显式 `null` 误当成缺失 | 不使用 `OmitNilData`，以请求 key 存在性决定 fields |
| 完整表单覆盖审计或租户列 | 验证前显式移除只读字段，租户 Hook 作为第二道保护 |
| 局部更新弱化父节点隔离 | 保留事务内父节点锁定和租户校验 |
| 性能优化改变不存在错误语义 | 保留现有目标行锁，不以受影响行数取代 |

## 11. 验收标准

1. `{"id":42,"isShow":false}` 只更新 `is_show` 和 `update_time`。
2. Vue 完整菜单表单可直接更新，不再返回 `未知字段: createTime`。
3. 菜单和部门更新不会把未提交列写成 `NULL`。
4. 明确提交的可空字段可清空，`false` 和 `0` 可正常保存。
5. `create_time`、`tenant_id` 和部门 `user_id` 不受客户端更新。
6. 未知字段、跨租户目标和跨租户父节点仍被拒绝。
7. 更新流程不增加数据库往返或新的第三方依赖。
