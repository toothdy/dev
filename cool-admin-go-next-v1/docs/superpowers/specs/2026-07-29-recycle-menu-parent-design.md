# 回收站菜单归位设计

## 目标

保证全新初始化数据库时，“数据回收站”显示在“数据管理”菜单下，不再成为顶级菜单。本次不迁移已经初始化的数据库。

## 方案

将“数据回收站”及其权限子菜单从 `modules/recycle/menu.json` 移回 `modules/base/menu.json` 的“数据管理”节点。Recycle 模块继续拥有数据库 seed、接口、服务和运行时，但不再注册独立菜单 seed。

不扩展菜单 seed 格式，也不增加跨模块父菜单引用。当前菜单导入器只能根据同一个 JSON 文件内的 `childMenus` 建立父子关系，将节点放回 Base 菜单树能够复用已有行为并保持初始化顺序稳定。

## 改动范围

- 在 Base 菜单树的“数据管理”节点下恢复“数据回收站”。
- 删除 Recycle 模块的独立菜单 seed 文件，并清空模块注册中的菜单路径。
- 更新 Recycle 模块测试，断言模块不再提供菜单 seed。
- 增加 Base 菜单结构测试，断言“数据回收站”是“数据管理”的直接子菜单。
- 更新 seed 集成测试，不再单独导入 Recycle 菜单。

## 初始化行为

全新初始化时，Base 菜单 seed 一次性写入“数据管理”和“数据回收站”的父子关系，并将这些菜单授权给 admin 角色。Recycle 模块不会再次写入相同菜单，也不会创建顶级节点。

已有 `init_menu_base` 或 `init_menu_recycle` 标记的数据库不会被修改，符合本次仅修复后续初始化的范围。

## 验证

- JSON 结构测试确认“数据回收站”位于“数据管理”下。
- 模块注册测试确认 Recycle 的菜单 seed 路径为空。
- seed 单元测试与相关 Go 测试通过。
- 检查代码库中不存在仍会导入 `modules/recycle/menu.json` 的引用。
